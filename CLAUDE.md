# shamirai.ai

A map of what Shami is learning, building, and has finished. Live at https://shamirai.ai.
The primary reader is Shami, not an audience. Unfinished nodes are valuable content, not
placeholders to hide.

## Adding or updating a topic

```bash
npm run new -- "Some Title" --cluster <key> [--state learning|executing|reported]
```

One markdown file per topic in `src/content/entries/`. Never hand-write these files when the
script will do it.

**Every entry uses the same five beats. Do not invent a different structure:**

```markdown
## The question
## What I built
## What surprised me
## What I'd do differently
```

**Never use an em dash (`—`) anywhere.** Not in entries, summaries, docs, code comments, commit
messages, or UI strings. Use a comma, a colon, parentheses, or split the sentence. This applies to
prose written in conversation about the project too.

Plus `repo:` / `live:` in frontmatter for the link. `summary:` is one line saying what the topic
*is*, not what was found. It is most of what the embedding has to work with on an unwritten
entry, so keep it specific.

States: `learning` (no body, exists to mark a gap) → `executing` (beats 1–2) → `reported` (all
four, plus `date:`).

Clusters are keys in `src/lib/clusters.ts`. Add one there before using it in frontmatter.

## Starting a project for a node

```bash
npm run project -- <slug> [--private]
```

Creates `../<slug>` (a sibling of this repo, inside `ai-projects/`), a GitHub repo of the same
name, writes `repo:` back into the entry, and flips `learning` → `executing`. It refuses any slug
that isn't already an entry. That guard is deliberate, so unrelated local work is never pushed to
GitHub. Do not weaken it.

**One name everywhere:** node slug = repo name = local directory name.

Not every node needs a repo. Plenty are pure reading and correctly have no `repo:` at all.

## Map positions

Resolved in three layers, most specific first: `position:` in frontmatter → `src/data/positions.json`
→ deterministic cluster fallback.

- **Never hand-edit `positions.json`.** It is generated by `npm run embed` and committed.
- The projection is deterministic: same content gives byte-identical output across machines and
  Node versions. A diff in that file always means content changed.
- CI recomputes it on every push and commits it back if it moved.
- To move one node without fighting the projection, set `position: [x, y]` in its frontmatter.

## Deploying

Push to `main`. CI type-checks, re-embeds, builds, and deploys to Cloudflare Pages. Any other
branch gets a preview URL. There is no manual deploy step.

## Constraints

- **Astro is pinned to 5.x** because 6 and 7 require Node ≥22.12 and this machine runs Node 20.
  The advisories on 5.x are unreachable here: static output, no SSR, no server islands, no
  untrusted input. Revisit after upgrading Node.
- `.env` holds Cloudflare credentials and is gitignored. Never commit it, never echo its contents.
- The map and the index are two views of the same content and exactly one is ever shown. The three
  rules that decide which live together under "surface switching" in `src/styles/global.css`.
  They must agree, so keep them together.
